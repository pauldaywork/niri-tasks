# Go to List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a **Go to…** button, first on every task card's action row, that opens a list in the panel of what can be done with the task and where it can be gone to: Refine (Redo refine), Grill me, Get started (Back to worktree), Generate report (Regenerate report), Open report, Planning doc, Design spec, Go to refine session, Go to work session, Open worktree folder, Open in VS Code and Read aloud, each row shown only when it applies. Go to session, Grill me, Report and Speak leave the row for the list.

**Architecture:** `TaskState` stops lumping the Claudes together (`has_work`, `has_refine`) and learns the linked documents (`has_spec`, `has_plan`, beside `has_report`). A new pure model, `src/panel/goto.rs`, turns a `TaskState` plus what the surface finds on the machine (`Found`: a worktree, VS Code, a speech playing) into rows (`Item`), their words and the `niritasks` words each spawns. `Action::GoTo` replaces `Session`, `Grill`, `Report` and `Speak` on the row; pressing it asks the surface to probe (`Effect::ListGoTo`), which hands back `Found`, and `Mode::GoTo(GoToList)` shows the list with the project list's keys, drawn with `draw_projects`'s pattern. The CLI gains `task session --work|--refine` and `task open <uuid> spec|plan|worktree|editor`. Ctrl+Enter keeps today's rule.

**Tech Stack:** Rust (`cargo test`, `cargo build`), clap 4 derive, GTK4 panel, herdr agents, git worktrees, taskwarrior notes, Nerd Font glyphs.

**Spec:** Taskwarrior task `77aee126-b9a4-47c9-b48e-6858f39683a1` (read it with `task rc.json.array=on 77aee126-b9a4-47c9-b48e-6858f39683a1 export`), as changed with the user on 2026-10-11: the list holds actions as well as destinations, four buttons move into it, and Ctrl+Enter is left alone. **Global Constraints** below are the spec as decided; where they differ from the task's notes, they win.

## Global Constraints

- **The button:** `Action::GoTo`, label `Go to…` (`…` is U+2026), key `o`, first on every card's row, on every task that is not processing, waiting and finished ones included (Read aloud and the documents work on any task). Icon Font Awesome's ellipsis `"\u{f141}"`, class `"go-to"`, colour mocha blue `#89b4fa` (Go to session's, renamed `style::GO_TO`). It opens the list in the panel, so it keeps the keyboard. It runs no command itself.
- **Leaving the row:** Go to session (`g`), Grill me (`i`), Report (`p`) and Speak. Their letters go, and Speak's spinner goes with its button. The row is then Go to…, Back to list, Start working, Refine, Edit, Up next, Complete, Move to workspace, Stop, Waiting, Remove: 9 buttons at most.
- **The list is a panel mode, not a window** (ADR 0003): a title line `Go to…: <description>`, one row per item with its own icon, Up and Down to pick, Enter or a click to do it, Escape back to the card with the keyboard kept. No text field. Footer: `Up, Down: pick · Enter: do it · Esc: back to the card`.
- **Rows, in this order, with when each shows and what it runs** (nothing at all on a processing task; "on the list" = not waiting or finished):

  | Row | Shows when | Runs |
  |---|---|---|
  | Refine / **Redo refine** once planned | on the list | `task refine <uuid>` |
  | Grill me | on the list | `task refine <uuid> --grill` |
  | Get started / **Back to worktree** once active | on the list | `task start <uuid>` |
  | Generate report / **Regenerate report** once a `Report:` note exists | on the list and planned | `task report <uuid> --fresh` |
  | Open report | a `Report:` note exists | `task report <uuid>` |
  | Planning doc | a `Plan:` note exists | `task open <uuid> plan` |
  | Design spec | a `Spec:` note exists | `task open <uuid> spec` |
  | Go to refine session | on the list, `task-<uuid8>` live | `task session <uuid> --refine` |
  | Go to work session | on the list, `work-<uuid8>` live | `task session <uuid> --work` |
  | Open worktree folder | the task has a worktree | `task open <uuid> worktree` |
  | Open in VS Code | `code` is on `$PATH` | `task open <uuid> editor` |
  | Read aloud / **Stop reading aloud** while any speech plays | always | `task speak <uuid>` |

- **Picking a row** gives the keyboard back and spawns its command, except Read aloud, which goes back to the cards keeping the keyboard (as Speak did).
- **Ctrl+Enter is unchanged:** Refine until planned, then Start working; on an active task with a live Claude (work or refine), `task session <uuid>`, giving the keyboard back. Its hint still reads `Ctrl+Enter: Go to session` there, though no button carries those words now.
- **`task session`:** bare keeps preferring the work Claude, then the refine; `--work` and `--refine` go to that one alone and fail when it is not running.
- **`task open <uuid> spec|plan|worktree|editor`:** spec/plan open the noted file with xdg-open through niri, as a report is (`refine::open_report_command`); the note's path is repo-relative, resolved in the task's worktree when it has one, else the workspace's `~/Projects` folder (`Workspace::folder`); an absolute path is kept. `worktree` opens a terminal there (`programs::terminal_command`). `editor` opens `code` on the worktree, else the project folder. No note, no file, no worktree or no `code` is an error (`notify::error` and exit 1), never a panic.
- **A task's worktree** is found with `git worktree list --porcelain` (quick, no status), by a `task/…-<uuid8>` branch.
- **The working Claude links the documents:** `work::plan_prompt` asks for `Plan: docs/superpowers/plans/<file>.md` via `niritasks task note` once the plan is saved, and `Spec: docs/superpowers/specs/<file>.md` for a design doc; `claude/rules/niri-tasks.md` says the same for any Claude on a task; the refine-task skill keeps `Spec:`/`Plan:` notes as it keeps `Report:` ones. No step writes a spec yet, so Design spec stays hidden in practice.
- **Done when:** unit tests cover which rows a state gets and their words, what each spawns, the keys, `Task::spec_path`/`plan_path`, worktree finding, path resolution and the new CLI parsing; `tests/link_pane.rs` and `tests/typed_task_number.rs` pass unchanged; `cargo build` prints no warnings and `cargo test` passes; README, CONTEXT.md and llms.txt describe Go to… and the new commands, and no longer the four buttons.
- **Out of scope:** changing Ctrl+Enter; finding a plan or spec by searching docs for the uuid; opening a document in an editor inside herdr; any change to the refine mod (`claude/refine-mod`).
- **README's Commands block and llms.txt are tested against clap** (`readme_commands_block_runs_every_subcommand_and_flag`, `llms_txt_runs_every_subcommand_and_flag` in `src/main.rs`): every new subcommand and long flag must appear there being run **in the same commit** that adds it.
- **Commits:** Conventional Commits, subject at most 72 characters, body wrapped at 72 saying what and why, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. The task's type is `feat`, scope `panel` for panel work.
- **Tests stay green at every commit.** Run `cargo build 2>&1 | grep -c warning` → `0` before each commit too.
- **Skill and rules changes only run after landing** (they load from `~/Projects/niri-tasks`, not the worktree): don't try to e2e-check Task 7 from the worktree.

```rust
/// `git worktree list --porcelain`. Matched by uuid alone, as

pub fn worktree_in_porcelain(porcelain: &str, uuid: &str) -> Option<PathBuf> {
    let suffix = format!("-{}", names::uuid8(uuid));
    let mut path = None;
    for line in porcelain.lines() {

            }
        }
    }
```

```rust
//! The Go to list: what can be done with a task and where it can be gone
//! to, which the task panel shows in place of the cards when the card's
//! Go to… is pressed — refining and starting it, its report, its plan and
//! spec, its two herdr sessions, its worktree, VS Code, and reading it
//! aloud — each row only when it applies, and what picking one runs. Plain
//! data, like the project list: the rows are read off the task's
//! `TaskState` and what the surface found on the machine ([`Found`]), and
//! `surface.rs` only draws what this says.

use crate::actions::{Action, TaskState};

/// The button's words, and the start of the list's title.
pub const LABEL: &str = "Go to…";

/// The footer while the Go to list shows. No text field: there are twelve
/// rows at most.
pub const GOTO_KEYS: &str = "Up, Down: pick · Enter: do it · Esc: back to the card";

/// What the rows need to know that the task's state does not say, found
/// by the surface as Go to… is pressed.
#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
pub struct Found {
    /// The task has a worktree (`work::worktree_path`).
    pub worktree: bool,
    /// VS Code (`code`) is on `$PATH`.
    pub editor: bool,
    /// A speech is playing or being got ready, any task's: reading aloud
    /// again stops it.
    pub speaking: bool,
}

/// One row on the Go to list.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Item {
    /// Work it up into a plan with Claude; again, once it has one.
    Refine,
    /// Refine, interviewing first.
    Grill,
    /// Its worktree and a Claude to plan it; back to both once started.
    Start,
    /// Claude builds the report of its plan, a fresh one if it has one.
    Report,
    /// The report its notes link, `Report: <path>`, in the browser.
    OpenReport,
    /// The plan its notes link, `Plan: <path>`.
    Plan,
    /// The design spec its notes link, `Spec: <path>`.
    Spec,
    /// Its refine Claude, `task-<uuid8>`, in the workspace's herdr session.
    RefineSession,
    /// Its working Claude, `work-<uuid8>`, there.
    WorkSession,
    /// A terminal in its worktree.
    Worktree,
    /// VS Code on its worktree, else the project folder.
    Editor,
    /// Read it aloud; or stop the speech playing.
    ReadAloud,
}

use Item::*;

impl Item {
    /// Every row, in the order the list shows the ones that apply.
    pub const ALL: [Item; 12] =
        [Refine, Grill, Start, Report, OpenReport, Plan, Spec, RefineSession, WorkSession, Worktree, Editor, ReadAloud];

    /// Whether the row shows for a task in `state`, with what was `found`.
    /// Refining, starting and the herdr sessions are for a task on the
    /// list, as their buttons were; generating a report for a planned one;
    /// the documents whenever the notes link them, the worktree whenever
    /// there is one, VS Code whenever it is installed, and reading aloud
    /// always. Nothing on a processing task: a Claude is writing it.
    pub fn applies(self, state: TaskState, found: Found) -> bool {
        if state.processing {
            return false;
        }
        let on_list = !state.off_list();
        match self {
            Refine | Grill | Start => on_list,
            Report => on_list && state.planned,
            OpenReport => state.has_report,
            Plan => state.has_plan,
            Spec => state.has_spec,
            RefineSession => on_list && state.has_refine,
            WorkSession => on_list && state.has_work,
            Worktree => found.worktree,
            Editor => found.editor,
            ReadAloud => true,
        }
    }

    /// The rows a task in `state` gets, in [`Item::ALL`]'s order.
    pub fn of(state: TaskState, found: Found) -> Vec<Item> {
        Self::ALL.into_iter().filter(|i| i.applies(state, found)).collect()
    }

    /// The row's words. Four read as the step they take: Redo refine on a
    /// planned task, Back to worktree on a started one, Regenerate report
    /// once one exists, and Stop reading aloud while a speech plays.
    pub fn label(self, state: TaskState, found: Found) -> &'static str {
        match self {
            Refine if state.planned => "Redo refine",
            Refine => "Refine",
            Grill => "Grill me",
            Start if state.active => "Back to worktree",
            Start => "Get started",
            Report if state.has_report => "Regenerate report",
            Report => "Generate report",
            OpenReport => "Open report",
            Plan => "Planning doc",
            Spec => "Design spec",
            RefineSession => "Go to refine session",
            WorkSession => "Go to work session",
            Worktree => "Open worktree folder",
            Editor => "Open in VS Code",
            ReadAloud if found.speaking => "Stop reading aloud",
            ReadAloud => "Read aloud",
        }
    }

    /// The row's glyph, from the Nerd Font the cards use; no two alike.
    /// Font Awesome's: magic wand (Refine's own), comments (Grill me's),
    /// play (Start's), file-text outline, file-text, numbered list,
    /// lightbulb, comments outline, terminal, open folder outline and code;
    /// Read aloud's speaker is Material Design's, Speak's old one.
    pub fn icon(self) -> &'static str {
        match self {
            Refine => "\u{f0d0}",
            Grill => "\u{f086}",
            Start => "\u{f04b}",
            Report => "\u{f0f6}",
            OpenReport => "\u{f15c}",
            Plan => "\u{f0cb}",
            Spec => "\u{f0eb}",
            RefineSession => "\u{f0e6}",
            WorkSession => "\u{f120}",
            Worktree => "\u{f115}",
            Editor => "\u{f121}",
            ReadAloud => "\u{f0580}",
        }
    }

    /// The `niritasks` arguments picking the row runs. Generate report
    /// always builds (`--fresh`); Open report opens the linked one, which
    /// `task report` rebuilds if its file has gone.
    pub fn args(self, uuid: &str) -> Vec<String> {
        let words: &[&str] = match self {
            Refine => return Action::Refine.args(uuid),
            Grill => &["task", "refine", uuid, "--grill"],
            Start => return Action::Start.args(uuid),
            Report => &["task", "report", uuid, "--fresh"],
            OpenReport => &["task", "report", uuid],
            Plan => &["task", "open", uuid, "plan"],
            Spec => &["task", "open", uuid, "spec"],
            RefineSession => &["task", "session", uuid, "--refine"],
            WorkSession => &["task", "session", uuid, "--work"],
            Worktree => &["task", "open", uuid, "worktree"],
            Editor => &["task", "open", uuid, "editor"],
            ReadAloud => &["task", "speak", uuid],
        };
        words.iter().map(|w| w.to_string()).collect()
    }

    /// Whether picking the row keeps the panel's keyboard: only Read
    /// aloud, which plays in the background, as Speak's button did. Every
    /// other row opens a herdr tab, a browser, a terminal or an editor,
    /// which takes it.
    pub fn keeps_keyboard(self) -> bool {
        self == ReadAloud
    }
}

/// The Go to list: the task it is for, its rows, and the one the highlight
/// is on.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct GoToList {
    uuid: String,
    /// The task's description, for the line over the rows.
    text: String,
    /// What the rows were picked by, for their words.
    state: TaskState,
    found: Found,
    rows: Vec<Item>,
    /// The row the highlight is on: Up, Down and Enter's.
    at: usize,
}

impl GoToList {
    /// The list for the task `uuid`, described `text`, in `state`, with
    /// what was `found`, the first row highlighted. None with no row: a
    /// processing task.
    pub fn new(uuid: &str, text: &str, state: TaskState, found: Found) -> Option<GoToList> {
        let rows = Item::of(state, found);
        (!rows.is_empty()).then(|| GoToList { uuid: uuid.into(), text: text.into(), state, found, rows, at: 0 })
    }

    /// The task the list is for.
    pub fn uuid(&self) -> &str {
        &self.uuid
    }

    pub fn rows(&self) -> &[Item] {
        &self.rows
    }

    /// The index in `rows` the highlight is on.
    pub fn at(&self) -> usize {
        self.at
    }

    /// Up or Down, stopping at the ends.
    pub fn step(&mut self, forward: bool) {
        self.at = super::keys::step(self.at, self.rows.len(), forward);
    }

    /// The row at `at`, for Enter or a click. None past the last.
    pub fn item(&self, at: usize) -> Option<Item> {
        self.rows.get(at).copied()
    }

    /// The line over the rows: the button's words and the task's.
    pub fn title(&self) -> String {
        format!("{LABEL}: {}", self.text)
    }

    /// A row as its card reads: the icon, then the words. The two spaces
    /// are the gap a task card leaves after its icon.
    pub fn row_label(&self, item: Item) -> String {
        format!("{}  {}", item.icon(), item.label(self.state, self.found))
    }
}
```
