# Go to List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the task card's Go to session with a Go to… action that opens a list in the panel of where the task can be gone to: its working Claude, its refine Claude, its refine report, its design spec and its implementation plan, each row shown only when that destination exists.

**Architecture:** `TaskState` stops lumping the Claudes together: `has_session` splits into `has_work` and `has_refine`, and `has_spec`/`has_plan` join `has_report`, read from `Spec:`/`Plan:` notes as `Report:` ones are. A new pure model, `src/panel/goto.rs`, turns a `TaskState` into rows (`Destination`) and each row into the `niritasks` words it spawns; `Mode::GoTo(GoToList)` in `src/panel/state.rs` shows it in place of the cards with the project list's keys, and `surface.rs` draws it with `draw_projects`'s pattern. The CLI gains `task session --work|--refine` and `task open <uuid> spec|plan`. The working Claude's prompt, the rules file and the refine-task skill make and keep the `Spec:`/`Plan:` notes.

**Tech Stack:** Rust (`cargo test`, `cargo build`), clap 4 derive, GTK4 panel, herdr agents, taskwarrior notes, Nerd Font glyphs.

**Spec:** Taskwarrior task `77aee126-b9a4-47c9-b48e-6858f39683a1`, "feat(panel): Go to list: sessions, report and docs". Read it with `task rc.json.array=on 77aee126-b9a4-47c9-b48e-6858f39683a1 export`; its notes are the spec and are quoted in **Global Constraints**.

## Global Constraints

- **The list is a panel mode, not a window** (ADR 0003): a title line with the task's description, one row per destination with its own icon, Up and Down to pick, Enter or a click to go, Escape back to the card with the keyboard kept. No text field.
- **Rows, in this order, and when each shows:** Go to work session (`work-<uuid8>` live), Go to refine session (`task-<uuid8>` live), Go to report (a `Report:` note), Go to spec (a `Spec:` note), Go to plan (a `Plan:` note).
- **The action:** `Action::Session` becomes `Action::GoTo`, label `Go to…` (the single character `…`, U+2026), keeping Session's key `g`, icon `"\u{f120}"`, colour `c::SESSION` and class `"session"`. It applies to a task on the list with at least one row; a processing task gets none. It opens the list in the panel, so it keeps the keyboard.
- **What each row spawns:** `task session <uuid> --work`, `task session <uuid> --refine`, `task report <uuid>`, `task open <uuid> spec`, `task open <uuid> plan`. Bare `task session <uuid>` keeps preferring the work Claude, then the refine.
- **`task open`:** opens the noted file with xdg-open through niri, as a report is (`refine::open_report_command`). A `Spec:`/`Plan:` path is repo-relative and resolved in the task's worktree when it has one, else the workspace's `~/Projects` folder (`Workspace::folder`); an absolute path is kept. No note, or a missing file, is an error (`notify::error` and exit 1), never a panic.
- **Ctrl+Enter (decided with the user: on any task, not only active ones):** a live work Claude → straight to it (`task session <uuid> --work`), keyboard given back; else, when Go to… applies → open the list; else Refine, or Start working once planned, as today (nothing on an active planned task). So a planned task with a `Report:` note opens the list rather than starting. The hint names what it does: `Ctrl+Enter: Work session` for the first (short, because `m: Move to workspace · Ctrl+Enter: Work session` must fit the 48 characters beside a 12-button row: see `hint_room` in `src/panel/actions.rs`), `Ctrl+Enter: Go to…` for the second.
- **The row's Report button stays** (it builds a report where there is none); the list's Go to report shows only once one is linked.
- **The working Claude links the documents:** `work::plan_prompt` asks for `Plan: docs/superpowers/plans/<file>.md` via `niritasks task note` once the plan is saved, and `Spec: docs/superpowers/specs/<file>.md` for a design doc. `claude/rules/niri-tasks.md` says the same for any Claude on a task; the refine-task skill keeps `Spec:`/`Plan:` notes as it keeps `Report:` ones. No step writes a spec yet, so no Go to spec row appears in practice yet.
- **Done when:** unit tests cover which rows a state gets, what each spawns, the Ctrl+Enter rule and hint, the keys, `Task::spec_path`/`plan_path`, the path resolution and the new CLI parsing; `tests/link_pane.rs` and `tests/typed_task_number.rs` pass unchanged; `cargo build` prints no warnings and `cargo test` passes; README, CONTEXT.md and llms.txt name the new action and commands.
- **Out of scope:** Go to… on waiting or finished tasks; finding a plan or spec by searching docs for the uuid; opening a document in an editor inside herdr; any change to the refine mod (`claude/refine-mod`).
- **README's Commands block and llms.txt are tested against clap** (`readme_commands_block_runs_every_subcommand_and_flag`, `llms_txt_runs_every_subcommand_and_flag` in `src/main.rs`): every new subcommand and long flag must appear there being run **in the same commit** that adds it.
- **Commits:** Conventional Commits, subject at most 72 characters, body wrapped at 72 saying what and why, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. The task's type is `feat`, scope `panel` for panel work.
- **Tests stay green at every commit.** Run `cargo build 2>&1 | grep -c warning` → `0` before each commit too.
- **Skill and rules changes only run after landing** (they load from `~/Projects/niri-tasks`, not the worktree): don't try to e2e-check Task 7 from the worktree.

/// Where a linked document is: an absolute path as it is; a relative one,
/// as the notes write them, in the task's worktree when it has one, else
/// the workspace's folder.
pub fn resolve(linked: &str, worktree: Option<&Path>, folder: &Path) -> PathBuf {
    let path = Path::new(linked);
    if path.is_absolute() {
        return path.to_path_buf();
    }
    worktree.unwrap_or(folder).join(path)
}

/// `task open`: open the document `task`'s notes link with xdg-open, and
/// say so. A task with no such note, or a file not there, is an error, which
/// `main` turns into a notification: the Go to list's row is gone by then.
pub fn open(ws: &Workspace, task: &Task, doc: Document) -> Result<()> {
    let linked = doc
        .linked(task)
        .with_context(|| format!("This task's notes link no {}: add a `{}<path>` note.", doc.name(), doc.note()))?;
    let worktree = work::worktree_path(ws, &task.uuid);
    let path = resolve(linked, worktree.as_deref(), &ws.folder(&Dirs::from_env()?));
    anyhow::ensure!(path.is_file(), "The {} is not there: {}", doc.name(), path.display());
    let shown = path.to_string_lossy();
    // xdg-open through niri, as a report is opened (`refine::open_report`),
    // so the viewer outlives the niritasks process a press spawned.
    niri::spawn(refine::open_report_command(&shown))
        .with_context(|| format!("could not open the {} {shown}", doc.name()))?;
    notify::tasks(&format!("Opened the {}: {}", doc.name(), task.description));
    Ok(())
}

//! Claude, its refine Claude, its refine report, its design spec and its
//! implementation plan — which the task panel shows in place of the cards
//! when the card's Go to… is pressed, and what picking a row runs. Plain
//! data, like the project list: the rows are read off the task's
//! `TaskState`, and `surface.rs` only draws what this says.

use crate::actions::{Action, TaskState};

/// One place a task can be gone to: a row on the Go to list.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Destination {
    /// Its working Claude, `work-<uuid8>`, which Start working names.
    Work,
    /// Its refine Claude, `task-<uuid8>`, which Refine names.
    Refine,
    /// The refine report its notes link as `Report: <path>`.
    Report,
    /// The design spec its notes link as `Spec: <path>`.
    Spec,
    /// The implementation plan its notes link as `Plan: <path>`.
    Plan,
}

use Destination::*;

/// The footer while the Go to list shows. No text field: there are five
/// rows at most.
pub const GOTO_KEYS: &str = "Up, Down: pick · Enter: go there · Esc: back to the card";

impl Destination {
    /// Every destination, in the order the list shows the ones a task has.
    pub const ALL: [Destination; 5] = [Work, Refine, Report, Spec, Plan];

    /// Whether a task in `state` has this to go to: that Claude live, or a
    /// note linking that document.
    pub fn applies(self, state: TaskState) -> bool {
        match self {
            Work => state.has_work,
            Refine => state.has_refine,
            Report => state.has_report,
            Spec => state.has_spec,
            Plan => state.has_plan,
        }
    }

    /// The rows a task in `state` gets, in [`Destination::ALL`]'s order.
    pub fn of(state: TaskState) -> Vec<Destination> {
        Self::ALL.into_iter().filter(|d| d.applies(state)).collect()
    }

    /// The row's words.
    pub fn label(self) -> &'static str {
        match self {
            Work => "Go to work session",
            Refine => "Go to refine session",
            Report => "Go to report",
            Spec => "Go to spec",
            Plan => "Go to plan",
        }
    }

    /// The row's glyph, from the Nerd Font the cards use; no two alike.
    pub fn icon(self) -> &'static str {
        match self {
            // Font Awesome's terminal, Go to…'s own: the Claude doing the work.
            Work => "\u{f120}",
            // Font Awesome's magic wand, Refine's own.
            Refine => "\u{f0d0}",
            // Font Awesome's file-text, Report's own.
            Report => "\u{f15c}",
            // Font Awesome's lightbulb: the design.
            Spec => "\u{f0eb}",
            // Font Awesome's numbered list: the plan's steps.
            Plan => "\u{f0cb}",
        }
    }

    /// The `niritasks` arguments picking the row runs. The report's are
    /// Report's own, which opens a linked report rather than building one.
    pub fn args(self, uuid: &str) -> Vec<String> {
        let words = match self {
            Work => ["task", "session", uuid, "--work"],
            Refine => ["task", "session", uuid, "--refine"],
            Report => return Action::Report.args(uuid),
            Spec => ["task", "open", uuid, "spec"],
            Plan => ["task", "open", uuid, "plan"],
        };
        words.iter().map(|w| w.to_string()).collect()
    }
}

/// The Go to list: the task it is for, its rows, and the one the highlight
/// is on.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct GoToList {
    uuid: String,
    /// The task's description, for the line over the rows.
    text: String,
    rows: Vec<Destination>,
    /// The row the highlight is on: Up, Down and Enter's.
    at: usize,
}

impl GoToList {
    /// The list for the task `uuid`, described `text`, in `state`, the
    /// first row highlighted. None with nowhere to go.
    pub fn new(uuid: &str, text: &str, state: TaskState) -> Option<GoToList> {
        let rows = Destination::of(state);
        (!rows.is_empty()).then(|| GoToList { uuid: uuid.into(), text: text.into(), rows, at: 0 })
    }

    /// The task the list is for.
    pub fn uuid(&self) -> &str {
        &self.uuid
    }

    pub fn rows(&self) -> &[Destination] {
        &self.rows
    }

    /// The index in `rows` the highlight is on.
    pub fn at(&self) -> usize {
        self.at
    }

    /// Up or Down, stopping at the ends.
    pub fn step(&mut self, forward: bool) {
        self.at = super::keys::step(self.at, self.rows.len(), forward);
    }

    /// Enter or a click at `at`: the row's `niritasks` arguments. None past
    /// the last row.
    pub fn pick(&self, at: usize) -> Option<Vec<String>> {
        self.rows.get(at).map(|d| d.args(&self.uuid))
    }

    /// The line over the rows: the action's words and the task's.
    pub fn title(&self) -> String {
        format!("{}: {}", Action::Session.label(TaskState::default()), self.text)
    }

    /// A row as its card reads: the icon, then the words. The two spaces
    /// are the gap a task card leaves after its icon.
    pub fn label(destination: Destination) -> String {
        format!("{}  {}", destination.icon(), destination.label())
    }
}
